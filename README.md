# proxmox-k8s-homelab

Self-hosted Kubernetes homelab on **Proxmox VE**, fully provisioned as code:

**OpenTofu/Terraform** builds the VMs → **Kubespray** (in Docker) installs the
cluster → **HashiCorp Vault** holds every credential → **ArgoCD + ingress-nginx +
MetalLB + Caddy bastion** expose your apps to the internet.

Built for people who want to learn self-hosting the way it's done in production:
GitOps, secrets management, private networks, and a bastion — not a `k3s` one-liner.

## Architecture

```
                        Internet
                           │
                     Cloudflare (TLS)
                           │  A record → <your-public-ip>
            ┌────────── home router (dst-nat :443) ─────────┐
            │  Server VLAN 192.168.1.0/24                   │
            │      │                                         │
            │      ├── NPM / edge proxy (192.168.1.253)      │
            │      └── BASTION (192.168.1.40 + 10.0.1.40)    │  ← only dual-homed host
            │             Caddy → ingress-nginx VIP 10.0.1.88│
            │  Proxmox VE .237 ── vmbr1: k8s VNET 10.0.1.0/24 (unrouted)
            │      ├── control-plane-00..02 (.20–.22)        │
            │      ├── k8s-worker-00..02     (.30–.32)       │
            │      └── kubespray deployer VM                 │
            └── NAS (192.168.1.254) — HashiCorp Vault :8200  │
```

Full traffic-path walkthrough with live header evidence: [docs/expose-architecture.md](docs/expose-architecture.md).

## Prerequisites

- Proxmox VE (single node is fine) with `vmbr0` (management) and `vmbr1` (k8s VNET) bridges
- OpenTofu (or Terraform ≥ 1.6) + `jq`
- A Linux host or NAS for Vault (any docker host works — scripts target Synology)
- SSH key pair you'll inject into every VM

## Quick start

```bash
# 0. One-time: least-privilege Proxmox user (run on the PVE node)
iac/scripts/InitialSetupTFUser/TfUserInit.sh

# 1. Stand up Vault, then store Proxmox creds + infra values
#    (KV v2 at proxmox/terraform-prov and proxmox/infra-<env>-tfvars — see iac/vault-config/)
iac/scripts/HCVault/InstallHCVault.sh          # deploy Vault
USERNAME=you iac/scripts/HCVault/RenewVaultCert.sh --deploy

# 2. Configure the cluster
cp iac/prod/terraform.tfvars.example iac/prod/terraform.tfvars   # fill in your values
cp iac/prod/ssh/id_ed25519.pub iac/prod/ssh/                     # your public key

# 3. Plan & apply (creds are read from Vault at plan time — nothing in git)
tofu -chdir iac/prod init
tofu -chdir iac/prod plan
tofu -chdir iac/prod apply    # ~45min: clones 8 VMs, runs Kubespray, saves passwords to Vault

# 4. Access
scripts/admin/gen-ssh-config.sh          # writes ~/.ssh/config.d/proxmox-k8s.conf
scripts/admin/k8s-tunnel.sh start        # kubectl via bastion tunnel
```

VM credentials (random-generated per VM) land in Vault at
`proxmox/<vm-name>-password` — retrieve with `vault kv get`.

## Security model

- **No secrets in git**: provider creds, subnets, bastion params, and the SSH key
  all live in Vault and are read at plan time. `.gitignore` blocks
  `*.tfstate*`, `*.tfvars`, `*.pem`, `.terraform/`.
- **Least privilege**: dedicated `terraform-prov@pve` Proxmox user (script-provisioned).
- **Isolation**: the k8s VNET (10.0.1.0/24) is unrouted; the bastion is the only
  dual-homed host and bridges HTTP only (`ip_forward=0`).
- **Rotation-friendly**: per-VM passwords are `random_password` with `keepers`;
  Vault TLS is regenerated by script (repo ↔ server stay in sync).
